# Intake and workspace

## Minimum to begin

The user identifies a product/service or product idea and a problem, direction or decision worth investigating. Accept a short message, a brief file, a project folder or existing discovery state. Infer what is available from the conversation and accessible project context; do not require a completed intake form.

Follow `references/human-checkpoints.md` for startup questions, the persistent product Canvas and the input/draft/review loop. A missing product context requires a human answer before analysis; a missing outcome requires asking and waiting, even when data files are available.

A named folder is a destination, not evidence. A brief is one possible source, not a required file format. If the context is too vague to name any useful next question, ask one focused question about the user, problem or business priority. Do not invent a product objective to populate the tree.

| Available input | How to use it |
|---|---|
| Product brief, users, business priority, constraints | Establish/reuse the context and frame the first decision |
| Outcome and metric definition | Reuse if accepted/current; otherwise propose it with its basis and unknowns |
| Only a business aim or feature request | Help identify the behavior and why it matters, or keep a working research question |
| CSV, exports, metric definitions | Inventory first; route a decision-relevant quantitative question to data-analysis |
| Interview transcripts, notes, support records | Establish sources and scope; use affinity-mapping only with suitable source evidence |
| Existing analyses, online research, competitor links | Reuse relevant current evidence, retaining attribution and limitations |
| Selected opportunity or ideas, test plans/results | Resume at that stage with its supporting context; do not restart earlier choices |
| Existing cycle state and tree | Recover the actual stage, pending reviews, sources and last visible revision |

No outcome in a brief is normal: first ask the user which outcome they want. If they do not know, record that answer and formulate a provisional goal or propose targeted early research for review; do not silently skip the startup question. Missing CSVs, interviews, a target value or deadline does not by itself block starting. It may limit which next decision is justified. Do not produce unsupported opportunity claims or pretend that absent sources were analyzed.

## Workspace

Resolve a product root from explicit paths, current project and local rules. Default to `supersprint/<cycle>/` inside that product, keeping one cycle per folder. Save a short entry point, stage narratives, state and material decisions. Suggested stage documents: `01-goal.md`, `02-signals.md`, `03-opportunities.md`, `04-ideas.md`, `05-experiments.md`, `06-results-and-decision.md`. Preserve suitable existing paths instead of renaming them for conformity.

Use `signals/<kind>/raw/` and `signals/<kind>/analysis/<run>/` when new source organization is needed. Existing raw paths may be referenced rather than copied; never rewrite raw source content. Categories are useful organization, not research quotas. Specialist artifacts retain their native names and subfolders.

## Handoff

Pass a specialist the actual question, decision, segment/population, time scope, selected inputs or search scope, known constraints, output directory and expected return. Register its artifacts and completion/review statuses in the cycle. Missing required specialist input leads to a named gap and a concrete way to gather it, not invented evidence.

Keep user choices and hypotheses separate from verified observations. Brief metrics can be stated but unverified; source definitions and computed values may later challenge them. A repeat-measurement window is distinct from an achievement deadline.

For opportunity selection, read `references/opportunity-prioritization.md` and route the candidate needs plus their goal/evidence to the bundled `pres-prioritization` skill. Reuse the current human input checkpoint and preserve existing accepted choices.
